# 平台安全开发实施方案（架构确认版）

> 依据：`平台安全开发提示词.docx`
> 架构：**单组织 · 多用户 · 数据共享 · 无组织层级**（用户 2026-09-20 确认）
> 状态：**方案阶段，尚未修改任何代码**

---

## 〇、架构确认结果

| 决策点 | 结论 | 简化效果 |
|--------|------|---------|
| 用户关系 | **同一家公司的同事**（老板 / 设计 / 客服） | ✅ 不需要多租户 |
| 数据隔离 | **所有人共享全部批次** | ✅ 不需要数据范围过滤 |
| 组织层级 | **不需要**，用户直接挂权限 | ✅ 权限模型从 5 层降为 **3 层** |
| 历史数据 | 归给**首个管理员账号** | 需一次性迁移脚本 |

**澄清一点**：「有真实客户数据」指的是**业务对象**（客户的门店、照片、联系方式），
不是「客户作为系统用户」。所以：

- ❌ 不需要多租户隔离
- ✅ 但需要**客户数据的字段脱敏**与**访问审计**

**工作量**：约 **10~18 天**（原估 15~25 天）

## 一、权限模型（简化版三层）

文档 §4 原为「用户—角色—权限—组织—数据范围」五层，本项目简化为：

```
用户 ──(多对多)── 角色 ──(多对多)── 权限
```

### 1.1 权限编码（唯一定义源 `app/security/permissions.py`）

```python
# ── 批次与生成 ──
batch.read              查看批次列表与图片
batch.create            创建新批次（消耗付费额度）
batch.delete            删除批次                    ← 高危
batch.export            导出打包下载

# ── 效果图 ──
effect.read             查看效果图
effect.generate         生成/补齐效果图
effect.background.manage 管理 AI 背景库（生成/删除）
effect.params.manage    调整效果图参数

# ── 配置 ──
settings.model.manage   管理模型与 API Key          ← 高危
settings.path.manage    修改输出路径                ← 高危
prompt.template.manage  修改提示词模板
store.manage            编辑门店数据（标题/配色）

# ── 系统 ──
system.user.manage      用户管理                    ← 高危
system.role.manage      角色与权限管理              ← 高危
system.session.manage   查看/强制下线会话
system.audit.read       查看审计日志
system.backup.manage    备份与恢复                  ← 高危
system.health.read      查看系统健康
```

**要求**（文档 §4）：前端导航、角色配置界面、接口校验、测试**全部从这一份定义生成**，
不允许前后端各维护一份。

### 1.2 角色模板（文档 §5，按本项目裁剪）

| 角色 | 说明 | 核心权限 |
|------|------|---------|
| **管理员** `admin` | 老板 / 负责人 | 全部权限 |
| **设计师** `designer` | 生成与调整设计 | `batch.*`（除 delete）、`effect.*`、`prompt.template.manage`、`store.manage` |
| **客服/运营** `operator` | 查看与导出 | `batch.read`、`batch.export`、`effect.read`、`effect.generate` |
| **审计员** `auditor` | 只读审计 | `system.audit.read`、`system.health.read`（**不能改业务数据**） |
| **系统运维** `ops` | 服务维护 | `system.health.read`、`system.backup.manage`（**不含业务审批**） |

**职责分离**（文档 §5）：`effect.background.manage` 与 `settings.model.manage` 不授予审计员。

### 1.3 客户数据字段权限

| 字段 | 默认可见性 |
|------|-----------|
| 门店名称、标题、配色 | 全部角色 |
| 客户联系电话 | **脱敏显示**（仅后 4 位），完整值需 `customer.contact.read` |
| 客户门店实拍照片 | 有 `batch.read` 即可（本机资产，不外发） |

## 二、数据模型

### 2.1 新增表/文件（`data/security.json` 或 SQLite）

```
users
  id            TEXT PK    稳定不可变 ID（ULID），不随用户名变化   §3.1
  login_name    TEXT UNIQUE 登录名（规范化后唯一）                  §3.3
  display_name  TEXT        显示姓名（非凭据，不决定权限）          §3.4
  password_hash TEXT        argon2id 哈希                          §3.7
  status        TEXT        pending|active|frozen|disabled          §3.5
  is_superadmin INTEGER     是否超级管理员
  mfa_secret    TEXT        可为空（管理员建议启用）                §3.9
  created_at    TEXT
  last_login_at TEXT

roles
  code          TEXT PK     如 designer
  name          TEXT        中文名
  is_builtin    INTEGER     内置角色不可删除

role_permissions
  role_code     TEXT
  permission    TEXT        FK → permissions 定义源

user_roles
  user_id       TEXT
  role_code     TEXT

sessions
  id            TEXT PK     会话 ID（登录后轮换）                   §3.10
  user_id       TEXT
  created_at    TEXT
  last_seen_at  TEXT        用于空闲超时
  expires_at    TEXT        绝对有效期
  ip            TEXT
  user_agent    TEXT
  revoked_at    TEXT        支持撤销                                §3.12

audit_log (追加写，不可改)
  id            TEXT PK
  at            TEXT
  actor_id      TEXT        操作者稳定 ID（非显示名）               §8
  actor_roles   TEXT        操作当时的角色快照
  module        TEXT
  action        TEXT
  target_type   TEXT        如 batch / store / user
  target_id     TEXT
  request_id    TEXT
  result        TEXT        success|denied|error
  error_kind    TEXT
  changes       TEXT        脱敏后的变更摘要
```

### 2.2 现有数据的新增字段

```
batch 的 manifest 增加：
  owner_user_id   TEXT   创建者（Q4：历史批次归首个管理员）
  created_by_name TEXT   冗余显示名（便于审计回溯）
```

> **Q4 迁移**：首次启动检测到「无任何用户」时，引导创建首个管理员，
> 并把现有 4 个批次 + 46 张 AI 背景的 `owner_user_id` 全部指向该账号。

## 三、接口改造清单

### 3.1 新增接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/api/auth/login` | 公开（限流） | 登录，返回会话 Cookie |
| POST | `/api/auth/logout` | 已登录 | 登出并撤销会话 |
| GET | `/api/auth/me` | 已登录 | 当前用户 + 权限清单（供前端渲染导航） |
| POST | `/api/auth/password` | 已登录 | 改密码（**成功后撤销其它会话**）§3.13 |
| GET | `/api/auth/sessions` | 已登录 | 我的登录设备 |
| DELETE | `/api/auth/sessions/{id}` | 已登录 | 撤销某个会话 |
| POST | `/api/auth/mfa/setup` | 管理员 | 启用 TOTP |
| GET/POST | `/api/admin/users...` | `system.user.manage` | 用户管理 |
| GET/POST | `/api/admin/roles...` | `system.role.manage` | 角色管理 |
| GET | `/api/admin/sessions` | `system.session.manage` | 会话监控 |
| GET | `/api/admin/audit` | `system.audit.read` | 审计检索 |
| GET | `/api/admin/health` | `system.health.read` | 系统健康 |

### 3.2 现有接口加权限（全部）

| 现有接口 | 需要的权限 |
|---------|-----------|
| `GET /api/state` | `batch.read` |
| `POST /api/run` / `run/new-batch` | `batch.create` |
| `POST /api/stop` | `batch.create` |
| `POST /api/effects/generate` | `effect.generate` |
| `POST /api/effect-backgrounds/generate` | `effect.background.manage` |
| `GET/POST /api/effect-params` | `effect.params.manage`（GET 可放宽为 read） |
| `GET/POST /api/settings` | `settings.model.manage` |
| `POST /api/settings/validate-path` | `settings.path.manage` |
| `POST /api/settings/test` | `settings.model.manage` |
| `POST /api/reference-assets` | `batch.create` |
| `POST /api/export/*` | `batch.export` |
| `POST /api/history/restore` | `batch.create` |
| `POST /api/regenerate` | `batch.create` |
| **`POST /api/settings/test` 的 `base_url`** | ⚠️ **同时加 SSRF 校验** |

**实现方式**：FastAPI 依赖注入

```python
@app.post("/api/run/new-batch")
async def api_run_new_batch(
    payload: dict | None = None,
    user: User = Depends(require_permission("batch.create")),
):
    ...
```

## 七、风险与兼容

| # | 风险 | 缓解 |
|---|------|------|
| R1 | 加认证后前端全部接口要带凭证 | 前端与后端**同一批次改**，阶段 1 完成后一起验证 |
| R2 | 历史批次归属迁移不可逆 | 迁移脚本**先备份** `data/` 与 manifest，且可回滚 |
| R3 | 多用户共用一个 API Key，用量无法归属 | manifest 记录 `created_by`；如需按人限额，另加配额字段（**当前不做**） |
| R4 | 改造期间功能中断 | 按阶段提交，每阶段跑完整回归；保留旧版本可回滚 |

## 八、明确不做（附理由）

| 不做 | 理由 |
|------|------|
| 多租户 / 组织隔离 | 已确认单组织（Q1/Q3） |
| 数据范围过滤（本人/本部门） | 已确认数据共享（Q2） |
| 审批流 / 消息机器人 | 无审批业务（文档 §10 不适用） |
| 自研密码算法 | 文档 §2.3 禁止；用 argon2id |
| 开放 `0.0.0.0` 后再补认证 | 空窗期等于无门禁，且 SSRF 立即可用 |
