## 二、🔴 P1：`flux_local` 静默忽略参考图（违反 AGENTS.md）

```python
# app/providers/flux_local.py
async def generate(self, req: GenerateRequest) -> GenerateResult:
    if req.negative_prompt:
        pass                      # 显式忽略负向词（有注释，可接受）
    if req.size != "1024x1024":
        raise ProviderError(...)  # 尺寸有检查
    if req.n != 1:
        raise ProviderError(...)  # 数量有检查

    payload = {"prompt": req.prompt, "width": 1024, "height": 1024}
    # ⚠️ 完全没有 references 检查！
```

**后果**：用户选「图生图」+ `flux_local` → **参考图被静默丢弃**，用户以为生效了。

**AGENTS.md 明确要求**：
> 图生图/多图生图必须**显式声明**是否支持，**不能静默降级**。

**修复**：
```python
references = list(req.extra.get("reference_images") or [])
if references:
    raise ProviderError(
        "FLUX 本地验证不支持图生图/多图生图，请改用 qwen-image-3.0、Seedream 或 Gemini",
        retryable=False, code="UNSUPPORTED_IMAGE_MODE",
    )
```

## 三、🔴 P2：能力声明缺字段 → 前端无法提前提示

`app/providers/base.py` 目前只有：

```python
supports_negative: bool = False   # 负向词
supports_n: bool = False          # 一次多张
```

**没有图生图能力字段** → 前端**无条件显示** 3 个 tab，用户可能：
1. 选 `flux_local` + 图生图 → **跑到一半才报错**（或静默忽略）
2. 选 `openai` + 某不支持 edits 的模型 → **收到晦涩的 API 错误**

**建议新增**：

```python
supports_image: bool = False          # 是否支持图生图
supports_multi_image: bool = False    # 是否支持多图生图
max_references: int = 0               # 最多参考图张数（0=不支持）
```

**各服务商声明**（按实测）：

| 服务商 | supports_image | supports_multi | max_refs |
|--------|---------------|---------------|----------|
| qwen（3.0 / 3.0-pro） | ✅ | ✅ | 3 |
| seedream | ✅ | ✅ | 3 |
| openai | ✅（需模型支持 edits） | ⚠️ 待确认 | 1~3 |
| gemini | ✅ | ✅ | 3 |
| **flux_local** | ❌ | ❌ | 0 |

**新增接口**：`GET /api/providers/capabilities` → 前端据此：
- **禁用**不支持的模式 tab（灰掉 + 提示原因）
- **限制**参考图上传数量
- **切换服务商时自动回落到 `text` 模式**（如果新服务商不支持当前模式）

## 四、🟠 P3：openai / gemini 缺少模型级检查

**现状**：
- `openai`：直接 POST `/images/edits`
- `gemini`：直接把参考图拼进 `inputs`

**问题**：模型不支持时报的是**API 原始错误**（用户看不懂）。

**建议**：像 qwen 那样加**模型白名单**：
```python
if references and self.model not in OPENAI_EDIT_MODELS:
    raise ProviderError("当前模型不支持图生图，请改选 XXX", code="UNSUPPORTED_IMAGE_MODE")
```

**价值**：错误在**本地**就抛出，不浪费一次 API 调用（省钱）。

## 五、🟡 P4：参考图处理的可用性改进

| # | 现状 | 建议 |
|---|------|------|
| 1 | 只校验大小（10MB）与 MIME | 加**最小尺寸**校验（如 ≥256px）—— 太小的参考图效果差 |
| 2 | 以 **data_url（base64）** 传递 | base64 膨胀 33%。10MB 图 → 13MB payload。建议**大图先压缩到合理边长**（如 1536px）再传 |
| 3 | 前端限制 1/3 张，但**没有可视反馈** | 显示"已选 2/3"、超出时明确提示 |
| 4 | 参考图**没有作用预览** | 生成前展示"将使用这 N 张参考图"，避免选错 |
| 5 | manifest 记录 `reference_assets` 元数据 ✅ | 已符合规范（不存 Base64） |
