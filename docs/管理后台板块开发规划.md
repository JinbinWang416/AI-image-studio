## 〇、先说清楚：两个 bug 已修

用户点菜单没反应，**不是页面没做，是点不进去**。两个真 bug：

### Bug 1：CSS 层叠上下文陷阱 → 遮罩盖住了菜单

```css
.topbar { position: sticky; z-index: 20; }   /* ← 这行创建了新层叠上下文 */
.menu   { z-index: 1200; }                    /* ← 只在 .topbar 内部有效 */
.menu-backdrop { z-index: 1100; }             /* ← body 直接子元素 */
```

比较层级时比的是**层叠上下文本身**：`.topbar(20)` **<** `.menu-backdrop(1100)`。

**结果**：遮罩盖在菜单上，用户点的其实是遮罩 → 只触发「关闭菜单」，链接跳转被吞掉。

**CDP 实测佐证**：
```
elementFromPoint(菜单项中心) → DIV.menu-backdrop   ← 不是 <a>
```

**修复**：`.topbar { z-index: 1300 }`，让父容器整体高于遮罩。

### Bug 2：锚点只在首次加载生效

```javascript
// 旧代码：只读一次 location.hash
const wantTab = (location.hash || '').replace('#', '').trim();
```

**问题**：在**同一个标签页内**从 `#users` 切到 `#roles` **不会重新加载页面**，启动逻辑不再执行 → 面板不变。

**修复**：加 `hashchange` 监听 + `querySelector` 判空（旧代码锚点拼错时会抛异常，被外层 catch 吞掉导致整页停摆）。

### 修复后实测（5/5 通过）

```
✅ #users     点击=CLICKED /admin#users      到达=/admin#users       面板=tab-users       行=5
✅ #roles     点击=CLICKED /admin#roles      到达=/admin#roles       面板=tab-roles       行=5
✅ #sessions  点击=CLICKED /admin#sessions   到达=/admin#sessions    面板=tab-sessions    行=1
✅ #audit     点击=CLICKED /admin#audit      到达=/admin#audit       面板=tab-audit       行=200
✅ #health    点击=CLICKED /admin#health     到达=/admin#health      面板=tab-health      行=0
```

> **排查教训**：中途多次误判为"点击无效"，实际是**测试脚本把中文传给 CDP 时编码损坏**，
> `indexOf('审计')` 永远匹配不到。改用 `href` 匹配（纯 ASCII）后立刻全绿。
> **测试脚本的编码问题会伪装成产品 bug。**

## 二、板块深化规划

### 板块 1：用户管理

| # | 新功能 | 价值 | 依赖 |
|---|--------|------|------|
| 1.1 | **搜索 / 筛选 / 分页** | 用户超过 20 个后必须 | 纯前端 |
| 1.2 | **批量操作**（多选 → 批量停用/改角色） | 人员变动时一次搞定 | 前端 + 复用现有接口 |
| 1.3 | **用户详情抽屉** | 点一行看全部信息 | 新接口 `/api/admin/users/{id}` |
| 1.4 | **该用户的操作记录** | 出问题时追溯 | 复用审计接口（按 actor_id 过滤） |
| 1.5 | **管理员重置密码** | 员工忘密码不用走 CLI | 新接口（需 `system.user.manage`） |
| 1.6 | **导出用户清单 CSV** | 交接/盘点 | 新接口 |
| 1.7 | 密码策略提示 | 创建时实时校验 | 纯前端（调用后端校验接口） |

**1.5 的安全要求**（重要）：
- 重置后**强制下次登录改密**（`must_change_password=True`）
- 撤销该用户**全部会话**
- **写审计**（`action=user.reset_password`，高危）
- **不允许**查看原密码（永远做不到，argon2id 不可逆）

## 五、安全边界

| 项 | 约束 |
|---|------|
| 接口 | 全部走 `require_permission` |
| 高危操作 | 重置密码 / 恢复备份 / 批量停用 → **二次确认 + 写审计** |
| 敏感信息 | 界面**绝不显示**密码哈希、token、API Key |
| 不改动 | `output/`、历史批次、`config/settings.json` |
| 回滚 | 新板块独立文件，删掉 + 还原 `admin.html` 即可 |
