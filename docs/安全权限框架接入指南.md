# 安全权限框架接入指南

> 面向：给本项目新增业务模块的开发者
> 目标：**三步接入权限**，不写重复代码、不漏鉴权

---

## 〇、三十秒版本

新增一个需要权限的接口，只要改 **两处**，前端**不用动**：

```python
# ① app/security/permissions.py —— 定义权限码
Permission("order.create", "创建订单", "订单", high_risk=True),

# ② app/web/access_rules.py —— 声明路径需要它
("POST", "/api/order/create", "order.create"),
```

**改完重启服务**（启动自检会校验一致性）。

---

## 一、为什么要"集中映射"而不是逐个加依赖

本项目有 46+ 个 API。如果每个接口自己写 `Depends(require_permission(...))`：

| 问题 | 后果 |
|------|------|
| **容易漏** | 新增接口忘加 → **越权入口** |
| **难审计** | 权限散落各处，无法一眼看出"谁能访问什么" |
| **改一处要改多处** | 权限码改名 → 满项目找 |

集中映射后，`access_rules.py` 的规则表**就是**完整的访问控制清单。

## 二、三步接入（详细）

### 第 1 步：定义权限码

`app/security/permissions.py`：

```python
PERMISSIONS: tuple[Permission, ...] = (
    ...
    Permission(
        "order.create",              # 编码：模块.动作（小写、点分隔）
        "创建订单",                   # 中文名（界面显示）
        "订单",                       # 分组（角色配置界面的分组标题）
        high_risk=True,              # 高危：变更需复核 + 必须审计
        description="会写入业务库并占用库存",
    ),
)
```

**命名约定**：

| 动作 | 建议后缀 |
|------|---------|
| 查看 | `.read` |
| 新建 | `.create` |
| 修改 | `.update` |
| 删除 | `.delete` |
| 导出 | `.export` |
| 审批 | `.approve` |
| 管理 | `.manage` |

**`high_risk=True` 的判断标准**：涉及**资金、密钥、权限授予、不可逆删除**。

### 第 2 步：声明路径映射

`app/web/access_rules.py` 的 `PATH_PERMISSION_RULES`：

```python
PATH_PERMISSION_RULES = (
    ...
    # (HTTP 方法 或 "*", 路径前缀, 所需权限)
    ("POST",   "/api/order/create",  "order.create"),
    ("GET",    "/api/order/list",    "order.read"),
    ("DELETE", "/api/order",         "order.delete"),
    ("*",      "/api/order/export",  "order.export"),
)
```

**匹配规则**：
- 先按 HTTP 方法过滤（`"*"` 匹配所有方法）
- 再取**最长前缀**匹配
- 权限为 `None` 表示"只需登录，无需特定权限"

**⚠️ 未登记的 `/api/*` 路径默认要求登录** ——
这是刻意的：新增接口即使忘了登记，也不会成为**匿名可访问**的入口。

### 第 3 步：前端自动生效

**不需要改前端。** 前端通过 `/api/auth/me` 拿到权限清单：

```javascript
// 任何页面都能用
if (window.__PERMS__.has('order.create')) {
  // 显示"新建订单"按钮
}
```

导航渲染由 `static/permissions-ui.js` 统一处理（已内置常见按钮的映射）。

若新按钮不在内置映射里，在 `permissions-ui.js` 的 `BUTTON_RULES` 加一行：

```javascript
const BUTTON_RULES = {
  'btn-new-order': 'order.create',     // ← 加这一行
};
```

## 三、后端接口里还要做什么

**大多数情况什么都不用做** —— 中间件已按路径拦截。

但以下两种情况需要**额外**处理：

### 3.1 需要拿到"当前用户"

```python
from .auth_routes import current_user
from ..security.users import User

@app.get("/api/order/mine")
async def my_orders(user: User = Depends(current_user)):
    return {"orders": repo.list_by_user(user.id)}
```

### 3.2 需要"数据级"判断（不只是功能级）

中间件管的是"**能不能用这个功能**"，管不了"**能不能操作这条数据**"。

```python
@app.delete("/api/order/{order_id}")
async def delete_order(order_id: str,
                       user: User = Depends(require_permission("order.delete"))):
    order = repo.get(order_id)
    if order is None:
        raise HTTPException(404, "订单不存在")
    # ⚠️ 数据级：非管理员只能删自己创建的
    if "admin" not in user.roles and order.owner_id != user.id:
        security.audit.log(
            action="order.delete", module="order", result="denied",
            actor_id=user.id, target_type="order", target_id=order_id,
            error_kind="not_owner",
        )
        raise HTTPException(403, "只能删除自己创建的订单")
    ...
```

**要点**：
- **不信任客户端传的 owner/role/org**（文档 §4）
- 拒绝时**写审计**（否则越权尝试无痕迹）

### 3.3 需要在接口内直接校验权限

```python
from .auth_routes import security

if not security.has_permission(user, "order.approve"):
    raise HTTPException(403, "没有审批权限")
```

## 四、必须遵守的约定

| # | 约定 | 原因 |
|---|------|------|
| 1 | **权限一律服务端校验**，前端隐藏菜单只是体验 | 隐藏菜单不等于安全（文档 §2.4） |
| 2 | **默认拒绝**：拿不准就给更严格的权限 | 文档 §2.5 |
| 3 | **不信任客户端**传的角色/组织/归属 | 文档 §4 |
| 4 | 敏感字段**默认脱敏**，用 `redact.py` | 文档 §4 字段权限 |
| 5 | 导出前**必须**过脱敏（`redact_csv_rows`） | 否则"界面看不到、导出能拿到" |
| 6 | 高危操作**必须写审计** | 文档 §8 |
| 7 | 不给用户授予**自己没有**的权限 | 防提权（`SecurityService.set_user_roles` 已实现） |
| 8 | 新增权限码后**重启服务** | 启动自检会校验一致性 |

## 五、启动自检（自动化保障）

服务启动时会校验**四处权限码一致**：

```
① permissions.py 的定义源
② access_rules.py 的路径映射
③ 接口里 require_permission("...") 的引用
④ 角色模板 ROLE_TEMPLATES 的引用
```

**任何一处出现"未定义的权限码" → 拒绝启动并列出差异。**

### 常见触发场景

| 现象 | 原因 | 修复 |
|------|------|------|
| 启动报"引用了未定义的权限码" | 拼写错误 / 改名后漏改 | 改回 `permissions.py` 里的正确码 |
| 启动报"已定义但无任何引用" | 漏登记路径映射 | 在 `access_rules.py` 补一行 |
| 服务突然起不来 | 上一条改动引入 | 按报错修，或应急 `SHS_SKIP_SELFCHECK=1` |

### 手动运行自检

```powershell
.\.venv\Scripts\python.exe tools\run_selfcheck.py
```

### 应急跳过（不推荐）

```powershell
$env:SHS_SKIP_SELFCHECK = "1"
```

## 六、写测试

每个新权限至少覆盖两条：

```python
def test_low_privilege_denied(self):
    """无权限 → 403"""
    staff = self.svc.users.create("s1", "员工", hash_password(PW), roles=["operator"])
    r = self.client.post("/api/order/create", json={...})
    self.assertEqual(r.status_code, 403)

def test_admin_allowed(self):
    """有权限 → 通过"""
    r = self.client.post("/api/order/create", json={...})
    self.assertEqual(r.status_code, 200)
```

**再加一条**：验证拒绝时**写了审计**：

```python
denied = self.audit.query(result="denied")
self.assertTrue(any(r["action"] == "access.denied" for r in denied))
```

## 七、完整示例：新增"客户管理"模块

### ① `permissions.py`

```python
Permission("customer.read", "查看客户", "客户数据"),
Permission("customer.create", "新建客户", "客户数据"),
Permission("customer.delete", "删除客户", "客户数据", high_risk=True),
```

### ② `access_rules.py`

```python
("GET",    "/api/customer", "customer.read"),
("POST",   "/api/customer", "customer.create"),
("DELETE", "/api/customer", "customer.delete"),
```

### ③ 角色模板（可选，给默认权限）

```python
"operator": {
    "permissions": [..., "customer.read"],
},
```

### ④ 接口（含数据级判断与脱敏）

```python
@app.get("/api/customer")
async def list_customers(user: User = Depends(current_user)):
    rows = repo.list_all()
    # 字段级脱敏：无 customer.contact.read 者看到 138****5678
    perms = security.permissions_of(user)
    return {"customers": redact_payload(rows, permissions=perms)}
```

### ⑤ 前端（自动生效）

```javascript
if (window.__PERMS__.has('customer.create')) {
  showCreateButton();
}
```

## 九、常见错误速查

| 错误 | 症状 | 修复 |
|------|------|------|
| 权限码写错 | 接口**永远 403** | 跑 `run_selfcheck.py` 找出来 |
| 忘登记路径映射 | 接口退化为"只需登录" | 在 `access_rules.py` 补一行 |
| 前端按钮隐藏了但接口没拦 | **越权** | 检查 `access_rules.py` |
| 改了权限码没重启 | 老进程仍用旧规则 | 重启服务 |
| 脱敏只做在界面 | 导出泄漏 | 导出前也调 `redact_csv_rows` |
| 拒绝访问没写审计 | 越权尝试无痕迹 | 参考 §3.2 的写法 |
