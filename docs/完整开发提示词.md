## 0. 项目画像（一句话）

一个**单机、单用户、重 I/O 与重 CPU 混合**的批处理图像生产工具。
核心矛盾不是"扛高并发"，而是**模块易扩展 + 长期可维护** ——
所以架构是「**模块化单体 + 边界上下文**」，不是微服务。

**业务流程**：选门店 + 选比例 → 调 AI 模型生成彩色贴纸设计图 →
合成到用户上传的门店玻璃实拍照片（效果图）→ 批次完成后自动导出印刷 TIF。

## 2. ⚠️ 不可破坏的行为（硬约束）

1. **「开始/继续当前批次」只执行当前批次快照中的未完成任务** ——
   不能被后来修改的范围、模型或比例改变。
2. **「重新生成（新批次）」用当前设置创建新目录，绝不覆盖旧批次。**
3. **当前选择的门店**决定主界面展示范围，也决定新批次创建的任务范围。
4. **贴纸设计图与效果图分别写入 `<门店>生成图`、`<门店>效果图`**，各自保留 manifest。
5. **真实效果图只能基于用户本机上传的门店玻璃照片**；
   缺少照片时只能输出并**明确标记「模拟门店背景」**，**不要把模拟图描述为实拍图**。
6. **V1/V2/V3 真实感规则必须保留**；新批次可逐级提高，**不能超过 V3**。
7. **图生图 / 多图生图必须显式声明是否支持，不能静默降级** ——
   不支持就在**本地报错**（`UNSUPPORTED_IMAGE_MODE`），避免白烧付费 API。

## 7. ⚠️ 已知陷阱（血泪教训，务必避开）

### 7.1 测试会污染 `settings.json`！（2026-09-24 实测）

在架构版跑 `unittest discover` 后，`config/settings.json` 被**大面积改回默认值**：

```
active_provider        qwen → mock          ← 服务商被换掉
providers.qwen.api_key 117 字符 → 空        ← API Key 被清空！
scope.store_indexes    ['01'] → 23 个       ← 范围从 1 个门店变全部（会多花钱）
generation.limit       6 → 0
prompt.version         v8 → 空
effect.params          17 键 → 缺失
prompt_quality.template 被替换
```

**影响**：跑完测试后服务配置被重置，用户直接使用会得到错误行为。

**当前处置**：从 `config/settings.json.bak-testprep` 还原。

**⚠️ 这是待修复的根因** —— 需要排查哪个测试写出了 `settings.json`，
并让测试**只操作临时目录**（`SettingsStore(path=tmp)`），**绝不碰真实配置**。

### 7.2 ⚠️ 两版之间同步：**只能打补丁，不能整体覆盖文件**（2026-09-25 实测）

架构版与原版的**导入路径不同**：

```python
# 原版（未重构）
from ..manifest import ManifestStore
import dataclasses; cfg = dataclasses.replace(cfg, output_root=X)

# 架构版（Phase 0+1 后）
from ..state.manifest_store import ManifestStore
cfg = with_config(cfg, output_root=X)
```

**事故**：修好原版的 `server.py` 后，我**直接整体复制**到架构版 → 一次性破坏两件事：
1. 33 处分包导入被覆盖回旧路径 → `ModuleNotFoundError`
2. 12 处 `with_config(` 被覆盖回 `dataclasses.replace(` → `Config.__init__() got an unexpected keyword argument`

**正确做法**：
- **在原版改完后，把 diff 手工应用到架构版**（或写针对性补丁脚本）
- **绝不 `Copy-Item` 整个 .py 文件**
- 同步后立即跑架构版的 `unittest`（308 个）确认

**唯一可以整体复制的是**：`app/web/static/*`（前端资源两版一致）—— 但 `server.py` **不行**。

### 7.3 ⚠️ 用 PowerShell 写 JSON 会加 BOM（2026-09-25 实测）

`Set-Content -Encoding UTF8` 在 **PowerShell 5.1 下会写入 UTF-8 BOM**，
而 **Python 的 `json.loads()` 不接受 BOM** → **整个配置文件读取失败**
→ 回落到内置默认值（表现为：服务商变 mock、API Key 变空、批次丢失、界面空白）。

**症状很隐蔽**：用 PowerShell 检查配置"看起来完全正常"（PowerShell 能处理 BOM）。

**正确做法**：
```powershell
# ❌ 不要这样写 JSON
$obj | ConvertTo-Json | Set-Content $p -Encoding UTF8

# ✅ 要么交给 Python
.\.venv\Scripts\python.exe -c "import json,pathlib; ..."
# ✅ 要么指定无 BOM
[IO.File]::WriteAllText($p, $json, [Text.UTF8Encoding]::new($false))
```

**排查工具**：`tools/fix_json_bom.py`（扫描全项目并去 BOM）
