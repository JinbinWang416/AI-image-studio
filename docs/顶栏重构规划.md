## 二、本项目现状

当前顶栏（`index.html` 第 20~38 行）：

```
┌────────────────────────────────────────────────────────────────────┐
│ [◈] AI图片生成          [● 当前配置] [⚙ 设置] [▶ 开始] [✨ 重新生成] [■ 停止] │
│     23 套门店 × 6 张 = 138 张 …                                     │
└────────────────────────────────────────────────────────────────────┘
```

**问题**：
1. **品牌副标题写的是规格**（"23 套门店 × 6 张"），不是业务定位
2. **账号相关与业务操作混在一起**：设置（业务）和账号（系统）都在同一排
3. 我上一轮加的 `auth-badge`（账号角标）也是塞在 `controls` 里，位置随意
4. 没有"系统管理"入口 —— 管理后台只能手敲 `/admin` 网址

## 三、改造方案

### 3.1 品牌区

| 项 | 现状 | 改为 |
|----|------|------|
| 主名 | AI图片生成 | **AI生图平台** |
| 副标题 | 23 套门店 × 6 张 = 138 张 · 可选比例玻璃静电贴设计图 | **门店玻璃贴纸智能设计平台** |
| LOGO | `◈` 字符 | 保留（或后续换成真实 LOGO） |

> 规格说明（"23 套门店 × 6 张"）**下移到状态栏**，那里本来就有进度区，更合适。

### 3.2 三段式顶栏

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ① 品牌区                    ② 业务操作                 ③ 账号区            │
│ ┌──┐ AI生图平台          [● 当前配置]              [系统管理▾] │ 王金斌 ▾ │ ⚙ │
│ │◈ │ 门店玻璃贴纸智能设计平台 [▶开始][✨重新生成][■停止]                    │
│ └──┘                                                                     │
└──────────────────────────────────────────────────────────────────────────┘
```

**三段职责**：
| 区 | 内容 | 说明 |
|----|------|------|
| ① 品牌 | LOGO + 名称 + 副标题 | 固定不动 |
| ② 业务操作 | 当前配置状态 + 开始/重新生成/停止 | **干活的地方** |
| ③ 账号 | 系统管理▾ · 用户名▾ · ⚙设置 | **管理自己的地方** |

**关键**：③ 用一条**竖分隔线**与 ② 隔开（参考图里也是这么做的），视觉上区分「业务」与「账号」。

### 3.3 「系统管理」下拉菜单

菜单项**按权限动态生成**（无权限的项不显示）：

| 菜单项 | 需要的权限 | 跳转 |
|--------|-----------|------|
| 管理后台首页 | 任一管理权限 | `/admin` |
| 用户管理 | `system.user.manage` | `/admin#users` |
| 角色与权限 | `system.role.manage` | `/admin#roles` |
| 会话监控 | `system.session.manage` | `/admin#sessions` |
| 审计中心 | `system.audit.read` | `/admin#audit` |
| 系统健康 | `system.health.read` | `/admin#health` |

- **没有任何管理权限** → 整个「系统管理」按钮**不显示**
- 有权限时显示，点开是下拉面板

### 3.4 「用户名」下拉菜单

| 菜单项 | 说明 |
|--------|------|
| 头像/姓名（不可点） | 显示 `display_name` 与角色标签 |
| 我的登录设备 | 展开会话列表，可逐个撤销 |
| 修改密码 | 内联表单（原密码 + 新密码 + 确认） |
| 动态验证码 (MFA) | 启用/关闭 TOTP，显示密钥与二维码 URI |
| 退出登录 | 调用 `/api/auth/logout` |

> 这些接口**已经全部实现**（`/api/auth/sessions`、`/api/auth/password`、`/api/auth/mfa/*`、`/api/auth/logout`），只是还没有界面。

### 3.5 「设置」齿轮

保留现有的业务设置（模型服务商、API Key、范围、输出路径、效果图微调等）。

**变化**：从 `[⚙ 设置]` 文字按钮 → **纯齿轮图标**（与参考图一致），鼠标悬停显示"设置"。

### 3.6 状态栏补充

原品牌副标题里的规格信息下移：

```
┌────────────────────────────────────────────────────────────────┐
│ ████████░░░░░░  42%      58 / 138 张                            │
│ 23 套门店 × 6 张 · 当前批次 …                                   │
└────────────────────────────────────────────────────────────────┘
```

## 四、权限联动（与安全框架对接）

| 元素 | 权限要求 | 无权限时 |
|------|---------|---------|
| 系统管理（整个按钮） | 任一 `system.*` | **隐藏** |
| 菜单内的各项 | 对应权限码 | **单项隐藏** |
| 用户名菜单 | 登录即可 | — |
| 修改密码 / 我的设备 | 登录即可 | — |
| MFA 设置 | 登录即可 | — |
| 业务操作按钮 | `batch.create` 等 | 隐藏（**已实现**） |

> 服务端的拦截不变 —— 隐藏只是体验优化（文档 §2.4）。
