# 效果图优化方案（诊断稿 · 待调研回填）

> 状态：**诊断完成，竞品调研进行中，等待开发命令**
> 触发原因：用户反馈「效果图不理想」

---

## 一、现状诊断

### 1.1 当前实现链路

`app/effect_renderer.py` → `render_storefront_glass()`：

```
生成图(PNG) 
  → 把与边缘连通的白色变透明（_remove_outer_white）
  → 缩放到玻璃区域 68%×64%
  → 施加轻微仿射剪切（perspective = 0.030 + level×0.008）
  → 贴上，位置固定：水平居中、垂直 42%
  → 加高斯模糊阴影（固定右下偏移）
  → 加"反光"：一条白色斜多边形 + 一条白线
  → 加手机颗粒 + 暗角
  → 输出
```

### 1.2 背景来源

| 模式 | 触发条件 | 实现 |
|------|----------|------|
| `real_photo` | 用户上传了门店玻璃照片 | 照片铺满画布，玻璃区按硬编码 10%~90% |
| `simulated_storefront` | **未上传照片（当前就是这种情况）** | `_draw_simulated_storefront()` 用 PIL 画几何色块 |

**实测确认**：`output/_effect_backgrounds` 目录不存在 → **当前所有效果图都用的模拟背景**。

### 1.3 实际效果（已看图确认）

现有效果图的问题，按严重程度排序：

| # | 问题 | 具体表现 | 根因 |
|---|------|----------|------|
| **1** | **背景是"假的"** | 顶部深色块当门头、中间深蓝绿矩形当玻璃、几个模糊椭圆当店内灯光、绿色椭圆当绿植 | 背景由 PIL 几何图形绘制，本质是示意图而非照片 |
| **2** | **反光是画上去的** | 两条生硬白色斜带，与背景光线方向无关 | 固定多边形，未从照片提取 |
| **3** | **透视几乎无效** | `perspective` 仅 3.8%~5.4% 剪切 | 参数过小，且是仿射剪切而非真透视变换 |
| **4** | **位置固定** | 永远水平居中、垂直 42% | 未识别背景中的实际玻璃位置 |
| **5** | **阴影方向固定** | 一律右下偏移 | 未分析光源方向 |
| **6** | **贴纸"浮"在表面** | 缺少边缘厚度、接触阴影、玻璃叠色 | 只是 alpha 叠加 |
| **7** | **比例偏小** | 贴纸仅占玻璃区 68%×64%，周围大片空白 | 参数保守 |
| **8** | **无景深** | 背景完全清晰 | 未模拟手机拍摄的浅景深 |

## 二、参考样本分析（用户提供的目标）

用户提供了样本对：`参考图片/生成图/鲜花生成图.png` ↔ `参考图片/效果图/鲜花效果图.png`

### 2.1 样本对比

| | 生成图（设计稿） | 效果图（目标形态） |
|---|---|---|
| 背景 | 纯白 | **真实花店玻璃窗实拍** |
| 内容 | 粉色玫瑰花束 + "鲜花预订/花礼定制" | 贴纸贴在玻璃上，**透过玻璃能看到店内**：货架、花材、暖色灯光、绿植 |
| 玻璃表现 | 无 | **明显的对角线反光带**、玻璃边缘可见黑色窗框 |
| 拍摄质感 | 无 | 偏暗、有噪点、轻微失焦、有透视（侧面拍摄） |
| 贴纸占比 | 满幅 | 约占画面 **60%**，位于视线中心 |
| 融合度 | — | 贴纸边缘与玻璃自然过渡，**有轻微的玻璃叠色** |

### 2.2 另一份参考（供货商主图）

`参考图片/效果图/16a937e5….jpg` 是一张**手机拍摄的电脑屏幕照片**，屏幕里显示的是供货商商品主图目录：

```
E:\张生成图\…\ZF31000001-000006（窗花1：1）花店\主图
```

说明：**成熟卖家的主图就是「真实门店玻璃 + 贴纸」的实拍效果图**，没有用几何示意背景。

### 2.3 核心结论

> **效果图的质量，主要取决于「背景是不是真实照片」，而不是合成算法的精细度。**
>
> 我们现在把 90% 的精力花在了合成参数上（透视/阴影/反光），
> 但背景本身就是假的 —— 这是效果不理想的**首要原因**。

## 三、优化方案（分层）

### 第 1 层：解决背景真实性（**优先级最高，立竿见影**）

#### 1A. 用 AI 生成真实感门店玻璃背景（新增能力）

项目已有 9 个图像服务商（qwen / openai / gemini / seedream / kling / zhipu / flux_local / custom / mock），
**可以直接用来生成"空的门店玻璃门"照片**，再合成贴纸。

- **符合约束**：AGENTS.md 要求「生成图始终作为唯一前景素材，中文文字和图案不会被另一个模型重绘」——
  我们只生成**空背景**（不含贴纸文字），贴纸仍由本地合成，不违反约束。
- **做法**：按行业预生成背景库，缓存到 `output/_effect_backgrounds/`，多个批次复用。
- **优势**：用户不需要拍照，也能得到真实感效果图。
- **注意**：生成的背景必须标记来源（如 `ai_generated_background`），不能冒充用户实拍。

#### 1B. 内置样机模板库

预置若干张高质量真实门店玻璃照片（正面 / 斜侧 / 白天 / 夜晚），用户选模板即可合成。
- 优点：零成本、稳定
- 缺点：所有客户看到同样的背景，缺乏个性化

#### 1C. 引导用户上传实拍（已支持，需强化）

现有上传功能可用，但没有引导。应增加：
- 拍摄指导（角度、距离、光线、避免逆光）
- 上传后展示预览与质量提示（如"照片过暗""玻璃区域未识别"）

### 第 2 层：提升合成质量

| # | 改进项 | 做法 |
|---|--------|------|
| 2.1 | **真实透视** | 用 `Image.Transform.PERSPECTIVE`（四点变换）替代仿射剪切；支持用户标记玻璃四角，或用边缘检测自动估计 |
| 2.2 | **反光取自背景** | 从背景照片的高光/明亮区域提取蒙版，叠加到贴纸上（模拟玻璃反射覆盖贴纸） |
| 2.3 | **光影匹配** | 估计背景主光方向（梯度分析），阴影方向随之调整 |
| 2.4 | **贴纸融入** | 边缘微厚度高光 + 接触阴影 + 玻璃叠色（贴纸受环境影响轻微偏色） |
| 2.5 | **景深** | 背景轻微高斯模糊，贴纸保持锐利（模拟对焦在贴纸上） |
| 2.6 | **拍摄质感** | 保留现有颗粒/暗角，按背景亮度自适应 |

### 第 3 层：交互与呈现

- 效果图与生成图**并排对比**预览
- 提供「背景来源」明确标识（实拍 / AI 生成 / 模板），可切换
- 效果图参数可视化调节（透视强度、反光强度、阴影）

### 5.3 ⭐ 可直接作为工具默认值的视觉参数

| 参数 | 实测范围 | 建议默认值 |
|------|----------|-----------|
| 画幅 | 1:1（800² 或 1500²） | 1:1 |
| 拍摄角度 | 正面平视 **80%** > 斜侧 15°~25° 15% > 特写 5% | 正面平视 |
| **贴纸占玻璃宽度** | 55% ~ 85%，**中位数 ≈70%** | **70%** |
| 贴纸占玻璃高度 | 45% ~ 75% | 60% |
| 垂直位置 | 中心落在画面 45%~50% 高度（离地 1.2~1.5m） | 47% |
| 玻璃四周留白 | 10% ~ 20% | 15% |
| **边界约束** | **绝不跨过门框/竖梃**，须完整落在单扇玻璃内 | 强制校验 |
| 背景模糊 | **整体统一高斯模糊**，半径 ≈ 画面宽 1.5%~3% | 2% |
| 色温 | 室内 3200~3800K 暖光；横向线性光带 | 3500K |
| 玻璃反光 | **约 60% 的合成图完全没有反光** | 可选，弱叠加 |

> 另注：**所有合成效果图都没有贴纸边缘阴影/厚度/投影 —— 100% 纯平色块**。
> 也就是说「零厚度」本身不构成破绽，但**配合景深分层**才会显得自然。

### 5.4 合成图破绽清单（每条附修法）

| # | 破绽 | 修法 |
|---|------|------|
| 1 | 无玻璃反光 | 叠加低透明度环境反射 / 线性高光 |
| 2 | **贴纸过亮、自带发光** | 用环境光**归一化贴纸亮度** |
| 3 | 边缘数学级锐利、零厚度 | 0.5~2px 羽化 + 极轻外侧微阴影 |
| 4 | 背景该模糊却清晰、无透光衰减 | 贴纸须带轻微**透光** |
| 5 | 透视角度不匹配 | 做与玻璃同平面的**单应变换** |
| 6 | 色温不统一 | 按背景白平衡做**色调映射** |
| 7 | 全图均匀模糊、无景深梯度 | **径向/线性渐变模糊** |
| 8 | 门框处穿帮 | 优先避开框体，或做正确遮挡遮罩 |

### 5.5 ⭐⭐ 最有价值的结论：自然感来自**分层**，不来自抠图

> **「自然感不来自贴纸抠得干净，而来自玻璃反光层与景深分层。」**
>
> 看起来自然的样本，都有玻璃反射或明显的景深结构；
> 看起来"贴上去"的，全都是**「背景模糊 + 贴纸最顶层」的两层结构**。

**建议把 `effect_renderer.py` 从 2 层改为 4 层：**

```
① 背景层（带景深模糊、色温基调）
② 贴纸层（亮度归一化 + 轻微透光 + 边缘羽化）
③ 玻璃反射/高光层（弱叠加，可用背景高光提取）
④ 前景层（暗角 + 色调统一 + 拍摄颗粒）
```

**三层景深配方**（最容易"骗过眼睛"）：前景锐利道具（抱枕/绿植/人物背影）+ 中景窗户 + 远景虚化。

## 五之二、调研对原诊断的修正

| 原诊断 | 调研修正 |
|--------|----------|
| 「反光是画上去的」列为问题 #2 | ⚠️ **修正**：60% 的真实商品合成图**根本没有反光**。反光是**可选项**，不是必需项。真正必需的是**景深分层**。 |
| 「无景深」列为问题 #8（最低优先级） | ⚠️ **提升**：景深分层是**自然感的首要来源**，应提到 P0 级。 |
| 「贴纸浮在表面」（缺厚度阴影） | ⚠️ **修正**：竞品 100% 都是零厚度纯平色块。**加厚度不是重点**，重点是亮度归一化与透光。 |
| 贴纸占比 68%×64% | ✅ 与竞品中位数（宽度 70%）接近，**基本合理**，可微调 |

## 七、✅ 闭环验证结果（2026-09-20 已完成）

### 7.1 交付内容

| 文件 | 变更 |
|------|------|
| `app/effect_renderer.py` | **重写为四层架构**，版本号 `four-layer-glass-v3` |
| `tools/gen_effect_background.py` | 新增：用图像服务商生成真实感门店玻璃背景 |
| `tools/verify_effect_v3.py` | 新增：模拟背景版闭环验证 |
| `tools/verify_effect_v3_ai.py` | 新增：AI 背景版三方对比验证 |

### 7.2 四层架构落地

```
① 背景层      景深模糊（整体 + 玻璃区较轻）+ 色温基调
② 贴纸层      亮度归一化 + 轻微透光(7%) + 边缘羽化
③ 玻璃反射层   柔和高光带，**压在贴纸之上**（关键）
④ 前景层      暖光统一(3500K) + 暗角 + 拍摄颗粒
```

### 7.3 三方对比实测

| 指标 | A 旧版（两层+几何背景） | B 新版四层（模拟背景） | **C 新版四层 + AI 背景** |
|------|------------------------|----------------------|------------------------|
| 画面平均亮度 | 108.0 | 101.3 | — |
| 对比度(标准差) | 74.3（过锐，显假） | 39.9 | **40.0** |
| 环境匹配度 | — | 1.01 | **0.95**（理想区间） |
| 背景真实感 | 几何色块 | 暖色模糊（抽象） | **真实玻璃门 + 店内陈设** |
| 单张耗时 | ~4s | 2.6~4.3s | 2.7~5.2s |

### 7.4 踩过的三个坑（重要）

| # | 坑 | 现象 | 解法 |
|---|----|------|------|
| 1 | **背景与生成图比例不一致** | 生成图 2:3 竖版，背景 1:1 → `ImageOps.fit` **裁掉左右 33%**，玻璃区错位 | 背景必须**按生成图同比例生成**（新增 `--size` 参数，默认 1024x1536） |
| 2 | **模型不听「单开」指令** | 提示写"单开玻璃门"，实际仍生成双开门 → 单扇只占 40%，贴纸被迫缩小到 28% | 改描述为「**一整块落地玻璃，占画面 80%，中间无任何竖框**」 |
| 3 | **双开门必须指定单扇** | 跨竖梃违反竞品约束 | 新增 `glass_region` 参数（归一化四角），按背景图逐一标定 |

### 7.11 背景自动匹配（2026-09-20 完成）

**背景来源优先级**（实现于 `_effect_render_options(cfg, store_name)`）：

```
① 用户在设置/批次快照中明确选择的背景（实拍 或 AI）
② 未选择时 → 按门店名自动匹配同行业的 AI 生成背景
③ 都命中不到 → 模拟背景（simulated_storefront）
```

**匹配算法**（`app/effect_background.py::pick_background_for_store`）：

1. `extra.store_hint` 与门店名**完全相等** → 命中
2. 否则**互相包含**（如「汽车补胎」↔「汽车补胎门店」）→ 取名字最具体的
3. 同一行业多张时取**最新创建**的
4. 只挑 `ai_generated_background`，**不会自动套用用户实拍**

**实测**：`tools/verify_background_match.py` → **23 / 23 命中**，边界用例正确回退。

### 7.12 ⚠️ 修复的两个来源标记 Bug

自动匹配接进来后，发现两处会把 **AI 背景冒充实拍**，已修复（涉及 AGENTS.md 的不可破坏约束）：

| # | Bug | 后果 | 修复 |
|---|-----|------|------|
| 1 | `_effect_background_public()` 只保留 6 个字段 | `kind` 与 `glass_region` 被丢弃，界面无法区分来源，贴纸可能跨门框 | 扩展白名单，保留 `kind / label / glass_region / provider / model / store_hint / door / size` |
| 2 | `_background_metadata()` 只要收到背景就标 `real_photo` | **AI 背景会显示成"用户实拍"**，违反明确标记要求 | 按 `asset.kind` 分三路：`real_photo` / `ai_generated` / `simulated`，各自附 `notice` |

**修复后实测**：

```
房屋中介   → mode=ai_generated   scene=ai_generated_storefront
             ⚠️ 此背景由 AI 生成…不是真实门店实拍，请勿作为实拍图使用。
不存在的行业 → mode=simulated      scene=simulated_storefront
```

### 7.10 关于「客户实拍返图」的建议（来自小红书调研的启发）

小红书调研虽然因登录墙失败，但给出了**一条比登录更有价值的路径**：

> 你们自己做门店贴纸生意，手中应有**客户安装完成后的实拍图**（买家秀 / 施工返图）。
> 这批素材完全真实、零获取成本、而且可以**精确标注**（你知道贴纸实际尺寸、材质、玻璃尺寸、拍摄时间）。

| 对比 | 竞品参考图 | **自己的客户返图** |
|------|-----------|------------------|
| 真实性 | 他人图片，可能有滤镜 | **完全真实** |
| 可标注性 | 只能目测估算 | **知道实际尺寸/材质/拍摄参数** |
| 版权 | 他人作品，仅可参考 | **自己产品的图，可自由使用** |
| 能否直接对比 | 不能（不同贴纸） | **能（同一张设计图的真实安装效果）** |

**用法**：拿一张自己贴纸的真实安装照，与我们的合成图并排，逐项校准参数
（贴纸占比、色温、反光强度、透光率、景深）。这比任何竞品参考都准。
